## PLUR integration mode and version

PLUR is treated as an upstream dependency (Apache-2.0). No fork, no
vendored code. Integration surface: **CLI bridge adapter** with
capability detection (literal `plur` binary, argv-only, `shell: false`,
30s capability cache, `PLUR_PATH`/`~/.plur` detection). **PLUR was not
installed in this environment**, so the shipped `LocalFallbackEngine`
(Pao-owned SQLite, deterministic term recall, engine id disclosed in
every result) is the exercised path; the PLUR adapter activates
automatically when the CLI appears. Upstream version detected: none
(command not found) — re-check `https://github.com/plur-ai/plur` before
first production bind.

## Security decisions

- Secret guard runs BEFORE every durable write and sync — 11 detector
  categories; audit stores category/field-path/fingerprint only.
- Scope writes never fall back to `global` on ambiguity (safe `local`).
- Project isolation enforced in read expansion + `canReadScope`
  (test-proven).
- Sync disabled by default; unknown profile → `MEMORY_SYNC_UNSAFE_REMOTE`;
  local scope/private visibility/secret findings always block; execute
  without PLUR → `engine_unavailable`.
- Memory body logging off by default; audit redaction via the shared
  20.35/20.28 stack.
- Candidate pipeline: auto-learn OFF stores candidates; operator
  approve/reject required for activation.

## Deviations from the specification

1. **PLUR absent** → local fallback engine ships as the working path;
   the spec's graceful-fallback rule (§0.E, §7) is satisfied and the
   engine is disclosed everywhere. No `@plur-ai/*` package was installed
   in this pass (dependency addition deferred to operator action).
2. Registry stores engram content (not only hashes) for audit/index —
   the spec's "unless needed" clause.
3. Sync execute implements preview + gating + engine-availability
   checks; actual `plur sync` invocation activates only with PLUR present.
4. MCP transport preference: the repo's existing WebMCP gateway is used
   (spec §10 "if the existing Pao MCP runtime supports server tool
   registration" — it does).
5. Route prefix `/api/agent-memory/*` (repo convention) instead of
   `/api/memory/*`, which Phase 20.41 already owns.

## Remaining limitations

- PLUR-specific features (activation/decay, upstream hybrid BM25+
  embeddings, outbox) activate only with PLUR installed; the fallback
  engine is deterministic term recall.
- Codex hook-trust verification is MANUAL by design.
- Sync executes only against a real PLUR engine.
- Reviewer Council QA hooks are wired as advisory candidates; automatic
  reviewer delegation is a follow-up.
